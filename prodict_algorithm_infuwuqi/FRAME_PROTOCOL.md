# ADS8688 双通道帧协议

## 结论：是双通道帧，但双通道由 STM32 数据内容决定

你提供的 ESP32 固件会生成以下帧头：

```text
#ADS8688 v1 rate=40000 secs=8 col=10000 blk=2000 nblk=160 ch=2 range=0x02 code=u16le\r\n
```

其中 `ch=2` 明确声明双通道。`frame_pipeline.py` 也强制要求 `ch == 2`，否则拒绝处理。

需要注意：ESP32 本身不采 ADC，也不判断两个通道是否真的不同。它从 STM32 串口精确接收 640,000 字节，再补上声明 `ch=2` 的头和 `#END` 尾。因此：

- **协议层面：确定是双通道帧。**
- **物理采样层面：需由 STM32 固件保证 160 个块确实按两个 ADC 通道交替输出。**
- 仅检查帧长度无法证明两个通道都接到了有效信号；要最终确认，应分别绘制奇数块和偶数块波形，检查两路是否有独立且合理的变化。

## 字节布局

```text
ASCII 头（CRLF 结束）
块 0：2000 个 uint16，小端，通道 1
块 1：2000 个 uint16，小端，通道 2
块 2：2000 个 uint16，小端，通道 1
块 3：2000 个 uint16，小端，通道 2
...
块 159：2000 个 uint16，小端，通道 2
ASCII 尾：#END ...\r\n
```

不是“A、B、A、B 每个采样点交替”，而是“每 2,000 点换一次通道”。服务器的代码依据是：

```python
blocks = codes.reshape((-1, block_len))
selected = blocks[SELECTED_CHANNEL - 1 :: channel_count].reshape(-1)
```

## 数量核算

| 项目 | 值 | 计算 |
| --- | ---: | --- |
| 二进制负载 | 640,000 字节 | `2000 × 160 × 2` |
| 总采样码数 | 320,000 点 | `640000 / 2` |
| 每通道块数 | 80 块 | `160 / 2` |
| 每通道点数 | 160,000 点 | `80 × 2000` |
| 每通道有效采样率 | 20,000 Hz | `40000 / 2` |
| 每通道时长 | 8 秒 | `160000 / 20000` |
| 旧模型实际使用 | 100,000 点 | 前 5 秒，通道 1 |

`col=10000` 当前没有参与服务器解析，不能用它推导负载长度；现役代码按 `blk × nblk × 2` 计算字节数。

## ESP32 在链路中的职责

归档固件位于 `硬件/ESP32/firmware/esp32_ads8688_http_forwarder.ino`，当前行为是：

1. 按键后打开激光，预热 5 秒。
2. 向 STM32 发送 `A5 5A 01` 采集命令。
3. 以 1,152,000 baud 从 UART1 接收恰好 640,000 字节。
4. 使用 PSRAM 保存完整帧。
5. 补协议头/尾，HTTP POST 到 `/api/upload/raw`。
6. 携带 `X-Device-Id: ESP32_001`，失败最多重试三次。

公开仓库中的 Wi-Fi 名称和密码已替换为占位符，烧录前在本地填写，禁止提交真实凭据。

## 推荐的双通道实测验证

在服务器保存一份真实 `.bin` 后，写一个只解析、不上传数据库的小工具，将：

- `blocks[0::2]` 拼成通道 1；
- `blocks[1::2]` 拼成通道 2；
- 分别输出最小值、最大值、均值、标准差和前几秒波形图；
- 比较两路相关系数，排查两路完全相同、某一路恒定或饱和。

当前文档能确认协议和服务器实现是双通道，不能代替这一步硬件实测。
