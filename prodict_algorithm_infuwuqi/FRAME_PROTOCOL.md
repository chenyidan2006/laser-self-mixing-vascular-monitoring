# ADS8688 双通道帧协议

## 结论：协议声明双通道，但当前归档 STM32 源码没有证明物理双通道

你提供的 ESP32 固件会生成以下帧头：

```text
#ADS8688 v1 rate=40000 secs=8 col=10000 blk=2000 nblk=160 ch=2 range=0x02 code=u16le\r\n
```

其中 `ch=2` 明确声明双通道。`frame_pipeline.py` 也强制要求 `ch == 2`，否则拒绝处理。

需要注意：ESP32 本身不采 ADC，也不判断两个通道是否真的不同。它从 STM32 串口精确接收 640,000 字节，再补上声明 `ch=2` 的头和 `#END` 尾。

进一步检查 Keil 工程后发现：`ADS8688_PROJ.uvprojx` 将 `User/src/ads8688.c` 排除编译，实际包含 `User/src/ads8_test.c`。该文件的 `read_ch()` 第一次发送 `MAN_2`，之后连续发送 `CONT`，没有明确交替选择第二个物理通道。因此：

- **协议层面：帧头声明 `ch=2`，服务器也按两路拆块。**
- **物理采样层面：当前归档源码更像连续读取 ADS8688 的一个手动通道，不能证明两个真实通道交替输出。**
- 仅检查帧长度无法证明两个通道都接到了有效信号；要最终确认，应分别绘制奇数块和偶数块波形，检查两路是否有独立且合理的变化。

## 字节布局

```text
ASCII 头（CRLF 结束）
块 0：2000 个 uint16，小端，通道 1
块 1：2000 个 uint16，小端，通道 2
块 2：2000 个 uint16，小端，通道 1
块 3：2000 个 uint16，小端，通道 2
...
块 159：2000 个 uint16，小端，通道 2
ASCII 尾：#END ...\r\n
```

不是“A、B、A、B 每个采样点交替”，而是“每 2,000 点换一次通道”。服务器的代码依据是：

```python
blocks = codes.reshape((-1, block_len))
selected = blocks[SELECTED_CHANNEL - 1 :: channel_count].reshape(-1)
```

## 数量核算

| 项目 | 值 | 计算 |
| --- | ---: | --- |
| 二进制负载 | 640,000 字节 | `2000 × 160 × 2` |
| 总采样码数 | 320,000 点 | `640000 / 2` |
| 每通道块数 | 80 块 | `160 / 2` |
| 每通道点数 | 160,000 点 | `80 × 2000` |
| 每通道有效采样率 | 20,000 Hz | `40000 / 2` |
| 每通道时长 | 8 秒 | `160000 / 20000` |
| 旧模型实际使用 | 100,000 点 | 前 5 秒，通道 1 |

以上“每通道”数字是服务器依据 `ch=2` 做出的协议解释。如果 STM32 实际只连续采一个通道，那么两个所谓通道只是同一数据流的交替块，`20,000 Hz/通道` 也不代表两个物理传感通道。

## 40 kHz 与 UART 1,152,000 baud 的计算

### 40 kHz 的设计依据与证据边界

项目聊天记录中的解释是：依据奈奎斯特采样定理，采样率需要高于信号最高频率的 2 倍；由于实际信号较差、采集卡未必足够精确，希望使用约 3–4 倍的工程裕量，讨论中先估到约 20 kHz，最终又把程序设置为 40 kHz。

这可以作为选型背景，但不是硬件参数证明。当前没有老师采集卡的型号、配置或带时间轴的原始数据，所以不能写成“老师的采集卡采样率就是 40 kHz”。也不能确定从 20 kHz 到 40 kHz 是双通道导致的乘 2；聊天记录更接近“继续加大采样裕量”的表述。

需要分别理解：

```text
奈奎斯特理论下限：采样率 > 2 × 信号最高有效频率
当前代码事实：TIM2 总触发率 = 40,000 Hz
当前协议解释：40,000 总点/s ÷ 2 组 = 20,000 点/s/组
```

后两行的 `÷2` 来自 `ch=2` 的服务器拆块方式，与奈奎斯特定理中的 `×2` 不是同一个概念。由于当前 STM32 源码尚未证明两个物理通道交替采样，`20,000 点/s/组` 只能视为协议解释。

STM32 系统时钟配置使 TIM2 输入时钟为 84 MHz；`Prescaler=83`、`Period=24`，所以：

```text
84,000,000 ÷ (83 + 1) ÷ (24 + 1) = 40,000 Hz
```

8 秒总量：

```text
40,000 点/s × 8 s = 320,000 个 uint16
320,000 × 2 bytes = 640,000 bytes
```

STM32 和 ESP32 的 UART 都配置为 1,152,000 baud、8N1。8N1 每字节包含 1 个起始位、8 个数据位和 1 个停止位，因此理论线上数据量为：

```text
640,000 bytes × 10 bit/byte = 6,400,000 bit
6,400,000 ÷ 1,152,000 = 5.56 s
```

STM32 每累积 2,000 点发送 4,000 字节：

```text
块产生间隔：2,000 ÷ 40,000 = 50 ms
块发送时间：4,000 × 10 ÷ 1,152,000 = 34.72 ms
```

所以当前波特率理论上可边采边发，并留约 15.28 ms/块的余量。

如果把 UART 改成 2,000,000 或 4,000,000 baud，整帧理论传输时间分别变为 3.20 秒和 1.60 秒；它们仍然只是串口速率，不会自动改变 TIM2 的 40 kHz 采样频率。当前 STM32 SPI1 的代码配置为 APB2 84 MHz 除以 16，即约 5.25 MHz，也不是 2 MHz 或 4 MHz。

`col=10000` 当前没有参与服务器解析，不能用它推导负载长度；现役代码按 `blk × nblk × 2` 计算字节数。

## ESP32 在链路中的职责

归档固件位于 `硬件/ESP32/firmware/esp32_ads8688_http_forwarder.ino`，当前行为是：

1. 按键后打开激光，预热 5 秒。
2. 向 STM32 发送 `A5 5A 01` 采集命令。
3. 以 1,152,000 baud 从 UART1 接收恰好 640,000 字节。
4. 使用 PSRAM 保存完整帧。
5. 补协议头/尾，HTTP POST 到 `/api/upload/raw`。
6. 携带 `X-Device-Id: ESP32_001`，失败最多重试三次。

公开仓库中的 Wi-Fi 名称和密码已替换为占位符，烧录前在本地填写，禁止提交真实凭据。

## 推荐的双通道实测验证

在服务器保存一份真实 `.bin` 后，写一个只解析、不上传数据库的小工具，将：

- `blocks[0::2]` 拼成通道 1；
- `blocks[1::2]` 拼成通道 2；
- 分别输出最小值、最大值、均值、标准差和前几秒波形图；
- 比较两路相关系数，排查两路完全相同、某一路恒定或饱和。

当前文档能确认协议和服务器实现是双通道，不能代替这一步硬件实测。
