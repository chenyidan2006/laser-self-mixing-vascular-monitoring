# STM32F407 + ADS8688 采集说明

## 工程入口

- CubeMX 配置：`CHEIVE/ADS8688_PROJ/ADS8688_PROJ.ioc`
- Keil 工程：`CHEIVE/ADS8688_PROJ/MDK-ARM/ADS8688_PROJ.uvprojx`
- 主程序：`CHEIVE/ADS8688_PROJ/Core/Src/main .c`
- 定时器：`Core/Src/tim.c`
- SPI：`Core/Src/spi .c`
- USART：`Core/Src/usart.c`
- 当前参与编译的 ADS8688 逻辑：`User/src/ads8_test.c`
- 参数和命令宏：`User/inc/ads8688.h`
- UART DMA：`User/src/app_usart.c`

文件名 `main .c`、`spi .c` 中确实带有空格，整理时不要擅自改名，否则 Keil 工程路径会失效。

归档构建的 `MDK-ARM/ADS8688_PROJ/ADS8688_PROJ.map` 可确认工程入口一直是 `ads8_test.o`。但该 `.map/.hex` 生成于 2025-12-25，而命令控制源码修改于 2026-10-08；旧二进制不包含最新版控制逻辑，不能直接烧录为现役版本。最新版源码需要重新 Build。

## 三份 ADS8688 源码的关系

| 文件 | 工程/链接证据 | 活跃采样路径 | 结论 |
| --- | --- | --- | --- |
| `ads8_test.c` | `.uvprojx` 收录；旧 `.map` 也链接 `ads8_test.o` | 40 kHz、8 秒、320,000 点、2,000 点 DMA 分块；第一次 `MAN_2`，随后 `CONT`；支持 ESP32 命令启动 | 当前最新版源码，需重新 Build |
| `ads8688.c` | `.uvprojx` 中 `IncludeInBuild=0` | `MAN_0` 单通道测试，约 10,000 点停止 | 被排除的早期测试版 |
| `ads8688 - 副本.c` | `.uvprojx` 未收录 | `ADS_Read_CH0_Raw()`/`MAN_0`；`acquisition_flag=false`；1,024 点停止 | 未完成或诊断副本，不是现有构建入口 |

`ads8688 - 副本.c` 内确实还能看到 `SAMPLE_RATE=40000`、8 秒、自动扫描寄存器及较大的缓冲区，但这些声明没有接入当前有效中断路径，部分示例主程序还位于 `#if 0`。因此不能只看常量就认定它是最终 8 秒双通道固件，也不要把它直接加入工程与 `ads8_test.c` 同时编译，否则会产生同名函数/中断符号冲突。

## 引脚与接口

| STM32F407 引脚 | 功能 | 连接对象 |
| --- | --- | --- |
| PA1 | `ADS8688_DAISY` | ADS8688 菊花链/数据格式控制，当前拉低 |
| PA4 | `ADS8688_CS` | ADS8688 片选，软件控制 |
| PA5 | SPI1 SCK | ADS8688 时钟 |
| PA6 | SPI1 MISO | ADS8688 数据输出 |
| PA7 | SPI1 MOSI | ADS8688 命令输入 |
| PA8 | `ADS8688_RST` | ADS8688 复位 |
| PA9 | USART1 TX | 接 ESP32-S3 GPIO18 |
| PA10 | USART1 RX | 接 ESP32-S3 GPIO17，接收 `A5 5A 01` 启动命令 |
| PA13/PA14 | SWDIO/SWCLK | ST-Link 下载调试 |

STM32 与 ESP32 必须共地，UART 为 3.3 V TTL，不能直接接 RS-232 电平。

## 当前采样流程

最新源码的实际流程是：

1. `main()` 初始化 GPIO、DMA、SPI1、USART1、TIM2。
2. `ADS8688_Init()` 复位 ADS8688，并将 `CHN_2_RANGE` 写为 `0x02`。
3. `main()` 虽保留一次 `ads8688_start_sample()` 调用，但未被命令授权时函数立即返回，因此上电保持空闲。
4. 主循环中的 `usart_tx_task()` 从 PA10 解析 `A5 5A 01`；仅在未采样、未发送时启动一次新采集。
5. TIM2 每次更新中断调用一次 `read_ch()` 并保存一个 `uint16` ADC 码。
6. 每积累 2,000 点，设置一个发送标志；主循环通过 DMA2 Stream7 发送 4,000 bytes。
7. 累计到 320,000 点后停止 TIM2；最后一个 DMA 块完成后发送 `#END ...\r\n` 状态行。

```text
40,000 点/s × 8 s = 320,000 点
320,000 点 × 2 bytes = 640,000 bytes
2,000 点/块 × 2 bytes = 4,000 bytes/块
320,000 / 2,000 = 160 块
```

`raw_data[4][10000]` 占约 80,000 bytes，并不是把整帧 640,000 bytes 一次性留在 STM32 RAM 中。工程用 4 行环形复用缓冲区，边采边通过 UART DMA 发给 ESP32。

## 40 kHz 怎样由定时器得到

TIM2 输入时钟为 84 MHz，生成代码配置：

```text
Prescaler = 83  → 除以 (83 + 1) = 84
Period    = 24  → 除以 (24 + 1) = 25
84,000,000 / 84 / 25 = 40,000 Hz
```

`.ioc` 仍保存 `Period=999`，对应 1 kHz，而不是 40 kHz。这表明有人在生成代码后手工改过 `tim.c`。若直接在 CubeMX 中重新生成，40 kHz 配置可能被覆盖。

## SPI 与输入量程

SPI1 的生成代码配置为：

- 主机模式；
- 16 bit 数据宽度；
- CPOL Low、第二个边沿采样，即常说的 SPI Mode 1；
- APB2 84 MHz / 16，约 5.25 Mbit/s；
- 软件片选 PA4。

`ads8_test.c` 写入 `CHN_2_RANGE = 0x02`。根据同文件注释，该编码对应双极性约 ±2.56 V。正式接模拟前端前仍应对照 ADS8688 数据手册和实际参考电压确认，不能只按注释判断允许输入范围。

## 现役单通道与旧版块交替记录

Keil 工程把 `User/src/ads8688.c` 标为 `IncludeInBuild=0`，实际编译 `ads8_test.c`。当前 `read_ch()` 第一次发送 `MAN_2`，以后发送 `CONT`，没有在两个通道间切换。学长也确认现役只采单通道；早期双通道代码后来已经注释/停用。

归档的 [`frame_fix_convert_plot.m`](../tools/matlab/frame_fix_convert_plot.m) 曾提供 `blockSel=1/2`，把奇偶 2,000 点块当作 A/B 两组。这是为旧版布局分析保留的工具选项，不是现役数据的正确解析。现役文件应首先使用 `blockSel=0` 查看完整连续 40 kHz 流；若要送入模型，应另按训练流程降到 20 kHz，而不是隔块抽取。8 个主图的用途见 [`tools/matlab/README.md`](../tools/matlab/README.md)。

因此：

- 可以确认 ADS8688 的一个手动通道被连续读取；
- 可以确认单通道采样率是 40 kHz；
- 可以确认每个采样为 16 bit，即两个二进制字节；
- 可以确认帧头 `ch=2` 与现役物理通道数不一致；
- 当前服务器把奇偶块当成两路属于解析错误，不是硬件事实。

现役链路验证应检查完整连续流在每个 2,000 点边界是否保持时间连续，并比较“均匀每隔一点降采样”和“错误隔块抽取”的波形/频谱。旧双通道文件只有在固件版本或强证据能够确认时才按奇偶块恢复。

## ESP32 启动命令已经对齐

ESP32 固件在激光预热 5 秒后发送：

```text
A5 5A 01
```

2026-10-08 版本已在 `app_usart.c::usart_take_start_command()` 中实现三字节状态机。USART1 保持全双工：PA10 轮询接收短命令，PA9/DMA 发送采样数据。`ads8_test.c` 还会检查采集、帧尾和 DMA 状态，忙时不会重复启动。

这次归档解决的是源码配套关系，不代表旧二进制已经更新。目录中的 `.hex/.map` 早于新源码，烧录前必须用 Keil 重新构建，并在串口上验证“按键前无采样、收到命令后单次输出 640,000 字节”的行为。

## UART 吞吐与丢块风险

项目负责人已确认正式链路使用 USART1 1,152,000 baud、8N1；这也与 STM32 和 ESP32 两端代码一致：

```text
每块产生时间 = 2,000 / 40,000 = 50 ms
每块理论发送时间 = 4,000 × 10 / 1,152,000 = 34.72 ms
理论余量 = 15.28 ms/块
```

理论上可以边采边发，但当前只用一个 `sample_flag` 表示待发块，并没有块队列。如果主循环被阻塞、DMA 超时或发送时间超过 50 ms，新标志可能覆盖旧状态，导致整块丢失。实机应使用逻辑分析仪检查连续 160 个块，并为块序号、DMA 错误和溢出增加计数。

## 手工编译与烧录

1. 用 Keil MDK 打开 `MDK-ARM/ADS8688_PROJ.uvprojx`。
2. 确认目标器件为 STM32F407VETx。
3. 在 Project 树确认 `ads8_test.c` 参与编译、`ads8688.c` 被排除，且不要误把未收录的 `ads8688 - 副本.c` 加入构建。
4. 先执行 Build，处理所有 error；不要忽略 UART/DMA/TIM 的 warning。
5. 用 ST-Link 连接 3.3 V、GND、SWDIO、SWCLK。
6. 断开激光和模拟输入，先下载并验证 SPI、TIM2、UART 波形。
7. 确认电源和量程后再连接模拟前端。

## 修改采样率时必须一起改什么

不要只修改 `SAMPLE_RATE`。当前 `SAMPLE_TOTAL_CNT` 仍硬编码 `40000`，协议头也写死 `rate=40000`。至少同时检查：

1. `ads8688.h` 的 `SAMPLE_RATE`、`SAMPLE_TOTAL_CNT`、`ARRIY_COLUMN`；
2. `tim.c` 的 Prescaler/Period，并同步 `.ioc`；
3. UART 是否仍能在下一块产生前发送完；
4. ESP32 的 `HEADERLESS_PAYLOAD_BYTES` 和 `GENERATED_FRAME_HEADER`；
5. 服务器帧长校验、通道拆分和模型输入点数；
6. 8 秒采集时长、激光开启时长和超时配置。

更稳妥的代码写法应把 `SAMPLE_TOTAL_CNT` 改成 `SAMPLE_SECONDS * SAMPLE_RATE`，并让 ESP32/服务器从同一版本化协议参数生成长度，而不是在多处重复写死数字。
